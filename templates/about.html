About CKDPredict 2.0

A machine-learning based Clinical Decision-Support System for Chronic Kidney Disease (CKD) risk assessment — built as an academic mini project.

How it works

  1. Lab report (PDF / image) → text via PDF parsing or Tesseract OCR → value extraction with unit conversion
  2. User verifies values → range checks reject implausible numbers
  3. Missing tests are treated as neutral (no contribution) — “not tested” is never read as “sick”; completeness is reported
  4. Explainable Boosting Machine → probability, CKD / No CKD, risk level (Low <30%, Moderate 30–70%, High ≥70%)
  5. Explanation: the EBM is additive, so the score is exactly intercept + one contribution per test. The bars show those contributions (no approximation).
  6. eGFR via CKD-EPI 2021 creatinine equation and KDIGO G-stage (separate from the ML model)

Stack

Python · Flask · scikit-learn · pandas · SQLite · pdfplumber · Tesseract OCR · OpenCV · ReportLab · HTML/CSS/JavaScript

Dataset

UCI Chronic Kidney Disease dataset (400 records, 24 attributes). 21 clinical inputs are collected; 15 laboratory values feed the model and 6 history/vitals items are shown as clinical context.

{% if m %}

Model

Explainable Boosting Machine (EBM, Microsoft Research InterpretML) — a glass-box boosted additive model. Compared with CatBoost and LightGBM using repeated 5-fold cross-validation; models within noise of the best were treated as equivalent and the most interpretable one was selected. Classic CKD-project algorithms (Random Forest, XGBoost, SVM, KNN, Naive Bayes, Logistic Regression…) were deliberately not used.

{% endif %}

Limitations (please read)

  • Trained on only 400 records from one source; not externally validated.
  • In the UCI data no non-CKD patient has hypertension, diabetes, pedal edema, anemia or poor appetite, so these are not given to the model (it would learn “risk factor = CKD”). They are shown as clinical context only.
  • Probability is the model's confidence on its training distribution, not a clinical probability.
  • OCR can misread scans — always verify extracted values.
  • Prototype only: no authentication, encryption or audit logging; not for clinical use.
⚕️ Decision-support aid. Requires professional medical confirmation; does not replace doctors or laboratory diagnosis.
