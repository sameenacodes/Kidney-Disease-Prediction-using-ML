# CKDPredict 2.0 — Explainable CKD Decision-Support System

Machine-learning based **clinical decision-support prototype** for Chronic Kidney Disease (CKD) risk assessment.
Upload a lab report → values are read (OCR) → Explainable Boosting Machine → probability, risk, eGFR stage and the factors behind the
result → saved to patient history with progression charts and a PDF report.

> Screening / decision-support aid only. Not a diagnosis; requires professional medical confirmation.

## Quick start

```bash
# Windows:  double-click run.bat        Linux/macOS:  ./run.sh
# or manually
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py                                          # open http://127.0.0.1:5000
```

**OCR needs Tesseract** for scanned images / scanned PDFs (text-based PDFs work without it):
- Windows: install from <https://github.com/UB-Mannheim/tesseract/wiki>, then `set TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe`
- Ubuntu: `sudo apt install tesseract-ocr` · macOS: `brew install tesseract`

Try it with the **dummy** reports in `sample_reports/` (fake patients, generated by `make_sample_reports.py`).

## What's new compared with v1

| Feature | Details |
|---|---|
| Lab-report reader | PDF text layer, or OCR (3 preprocessing variants + voting) → form auto-fill; user verifies; file is deleted immediately; unit conversion (µmol/L, g/L, BUN…); decimal-loss recovery |
| New model | **Explainable Boosting Machine (EBM, Microsoft Research InterpretML)** compared with CatBoost and LightGBM (repeated 5-fold CV). No Random Forest / XGBoost / SVM / KNN / Naive Bayes / Logistic Regression / plain neural net |
| Explainability | Exact per-patient contributions (the EBM is additive: score = intercept + one term per test) + global shape-function plots |
| eGFR + KDIGO stage | CKD-EPI 2021 (race-free), G1–G5 — separate from the ML model |
| Progression tracking | Per-patient eGFR + probability charts across assessments (`/patient/<name>`) |
| Safety flags | Borderline probability, missing inputs, implausible values, "doctor review" banner |
| Validation centre | Hold-out metrics, confusion matrix, ROC, model comparison, robustness with hidden inputs, **upload your own labelled CSV** |
| PDF report | Download from any result page |
| REST API | `POST /api/predict` |
| UI | Animated dark UI, English / தமிழ் toggle for key result text |

## Design decisions you should be able to explain (viva)

1. **Why are hypertension, diabetes, pedal edema, anemia, appetite and BP not in the model?**
   In the UCI data *none* of the 150 non-CKD patients has any of them, so a model fed these just learns "risk factor = CKD"
   — a diabetic with normal kidney labs would be flagged ~99 %. They are collected and shown as *clinical context* instead.
   (`ml/common.py → CONTEXT`.) The model uses 15 laboratory values.
2. **Missing values:** a test that was not provided is treated as *neutral* (contributes 0). In the UCI data missing values are more common in CKD rows, so a model that "reads" missingness would treat *not tested* as *sick*; neutral handling prevents that. The model is also trained on randomly-masked copies of the data. Completeness is reported and low completeness triggers a review flag.
3. **Why an EBM?** It is a modern (Microsoft Research, 2019+) glass-box boosted model: accuracy on par with CatBoost / LightGBM, but every prediction splits *exactly* into per-test contributions, so the explanation is the model itself (no SHAP/LIME approximation). Candidates within noise of the best recall/AUC are treated as equivalent and the most interpretable wins (`ml/train.py`). Classic CKD-project algorithms were deliberately not used.
4. **Probability ≠ clinical probability.** It is the model's estimate on its training distribution (EBM uses a logistic link; Brier score is in `models/metrics.json`).
5. **Risk levels:** Low < 30 %, Moderate 30–70 %, High ≥ 70 % of model probability.
6. **eGFR ≠ ML prediction.** eGFR is a formula (creatinine, age, sex); the ML model uses lab patterns.

## Honest limitations

- 400 records, single source, easily separable → near-perfect hold-out scores will **not** carry over to real patients; external validation is needed.
  With 40 % of inputs hidden, hold-out accuracy drops to about 97 % (shown on the Validation page). Hold-out is only 80 rows - treat the numbers as indicative, not proof.
- OCR was developed and tested on the dummy reports in this repo (PDF + scanned PNG: 16/16 values). Real lab layouts vary — always verify extracted values.
- Prototype security: no login, encryption or audit log. For production add authentication, HTTPS, encryption at rest, PostgreSQL.

## Project layout

```
app.py              Flask routes          db.py        SQLite (absolute path, data/patient_history.db)
report.py           PDF report            ml/train.py  train + compare + save model + plots
ml/engine.py        predict + explain     ml/ocr.py    lab-report reader
ml/egfr.py          CKD-EPI 2021 + stage  ml/common.py features, cleaning, EBM scoring helpers
templates/ static/  UI (HTML/CSS/JS)      tests/       pytest-style tests
models/             ckd_model.joblib, metrics.json    data/kidney_disease.csv   UCI CKD dataset
```

Retrain: `python ml/train.py` · Tests: `python tests/test_app.py` (or `pytest`) · Production: `gunicorn app:app`

## REST API

```bash
curl -X POST http://127.0.0.1:5000/api/predict -H "Content-Type: application/json" \
 -d '{"age":55,"sex":"M","sg":1.010,"al":3,"hemo":9.4,"sc":3.2,"pcv":28,"rc":3.4,"bu":78,"htn":"yes"}'
```
Returns prediction, probability, risk, eGFR/stage, flags and the explanation (≥ 4 values required).

Dataset: UCI Machine Learning Repository — Chronic Kidney Disease (Rubini, Soundarapandian & Eswaran, 2015), 400 records.
